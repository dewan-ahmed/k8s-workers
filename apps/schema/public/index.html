    Use from CI / terminal

    Send a manifest or rendered Helm output directly to POST /api/validate:

    curl -fsS 'https://schema.k8s.workers.dev/api/validate?version=1.30' \
  -H 'Content-Type: application/yaml' --data-binary @manifest.yaml -o report.json

    Raw uploads require the version query parameter and also accept application/x-yaml, text/yaml, and text/plain. For JSON, include the version and manifest in the body:

    curl -fsS https://schema.k8s.workers.dev/api/validate \
  -H 'Content-Type: application/json' \
  --data-binary '{"version":"1.30","manifest":"apiVersion: v1\nkind: ConfigMap\nmetadata:\n  name: app"}'

    The JSON report includes targetVersion, release, scannedResources, valid, invalid, skipped, resources (each with status, errors, and notes), and warnings.

    HTTP 200 means a report was produced, even when resources are invalid. Errors return JSON with an error message: 400 invalid input, 403 cross-origin POST, 405 wrong method, 413 size or resource limit, 415 unsupported content type, 429 rate limit, or 500 unexpected failure. See GET /api/config for supported versions.

    Fail CI on invalid or unvalidated resources and YAML warnings:

    jq -e '.scannedResources > 0 and .invalid == 0 and .skipped == 0 and (.warnings | length == 0)' report.json
    Schemas from the Kubernetes OpenAPI spec of each release's latest patch. This checks structure and common API naming rules, not admission webhooks, CEL rules, or cluster state.
